2. Introduction

This project is a Quarto slide website for STA258: Statistics with Applied Probability at the University of Toronto Mississauga.

The project is organized around chapter landing pages and chapter slide decks. The source files are written as .qmd files and rendered into .html files that students access through the course website.

Key features of this slides project:

  • Homepage where students access chapter pages.
  • Chapter landing pages inside Chapter Landing Pages/.
  • Reveal.js slide decks inside Chapter Slides/.
  • WebR code blocks so students can run R in the browser.
  • Quiz plugin slides with correct-answer explanations.
  • Static R plots placed beside examples.
  • Interactive JavaScript widgets written directly inside slide files.
  • PDF views created from slide links using ?print-pdf.
  • GitHub Pages output served from the docs/ folder.

3. How to Use This Help File

This document is intended for future maintainers, TAs, students, and professors who need to update the STA258 slides website or troubleshoot problems.

For most updates, use this short workflow:

  1. Edit the relevant source .qmd file.
  2. Render with Quarto.
  3. Check the rendered HTML in a browser.
  4. Commit and push the source changes and rendered output when needed.

Main rule: The source files are the files to maintain. The rendered files in docs/ are output files.

6. Slide Deck Standard

All chapter slide decks should follow the same general structure so the course feels consistent from chapter to chapter.

Element Standard for this project
YAML Use live-revealjs, WebR packages, MathJax, slide numbers, chalkboard, and the quiz plugin when quiz slides are used.
Theme Use the STA258 teal, blue, yellow, grey, and orange colour system.
Opening Title slide, course name, university name, and cat mascot image.
Roadmap Include a chapter roadmap near the beginning.
Content flow Definition → intuition → example → plot → R check → quiz.
Practice Use task boxes, WebR blocks, quizzes, and in-class examples.
Ending Chapter summary, up-next slide, and back-to-homepage button.

Recommended YAML pattern

---
pagetitle: "Chapter N: Chapter Title - Slides"
engine: knitr
format:
  live-revealjs:
    theme: simple
    transition: slide
    slide-number: true
    toc: false
    chalkboard: true
    footer: "STA258 | Chapter N"
    pdf-separate-fragments: false
    html-math-method: mathjax
    code-copy: true
    code-fold: false
    incremental: false
    width: 1280
    height: 720
    margin: 0.055
    center: false
revealjs-plugins:
  - quiz
webr:
  packages:
    - ggplot2
    - dplyr
live:
  show-solutions: true
---

Slide design classes to reuse

The existing slide decks use reusable CSS classes. Future chapters should reuse these where possible instead of creating unrelated new styles.

  • .defbox for definitions.
  • .examplebox for worked examples.
  • .thinkbox for interpretation or discussion prompts.
  • .taskbox for in-class activities.
  • .warnbox for warnings or common mistakes.
  • .stat-card for compact summary cards.
  • {.scrollable} for slides that need vertical scrolling.

7. File Paths and ../ Rules

Many problems in this slide project come from file paths. Always check where the current file is located before writing links.

Situation Path pattern
Root-level file, such as index.qmd images/cat.png, Chapter Landing Pages/chapterN.html, Chapter Slides/chapterN-slides.html
Landing page inside Chapter Landing Pages/ ../index.html, ../Chapter Slides/chapterN-slides.html, ../images/cat.png
Slide file inside Chapter Slides/ ../index.html, ../images/cat.png, ../_extensions/r-wasm/live/_knitr.qmd
Image from a root-level file images/cat.png
Image from a slide or landing page folder ../images/cat.png

Rule: If an image, homepage button, WebR include, or slide link does not work, first check whether the path needs ../.

8. In-Class Examples and Plots

In-class examples should usually appear as two slides:

  1. A prompt slide with a taskbox and a plot beside it.
  2. A WebR check slide where students can run the calculation.

Recommended structure

---

## In-Class Example: Example Title {.scrollable}

:::: {.two-col-wide}
::: {.col}
::: {.taskbox}
<span class="label">In-Class Example</span>

Question text goes here.

**(a)** First task.

**(b)** Second task.

**(c)** Interpretation question.
:::
:::

::: {.col}
```{r}
#| fig-width: 5.8
#| fig-height: 4
#| fig-align: center
#| echo: false

# Plot code goes here
```
:::
::::

---

## Example Title - Check in R

```{webr}
#| autorun: false

# Student-check code goes here
```

This structure keeps the slides interactive without making the main teaching slide too crowded.

9. WebR in Slides

WebR lets students run R code directly inside the browser.

A basic WebR chunk looks like this:

```{webr}
#| autorun: false

x <- c(2, 4, 6, 8)
mean(x)
sd(x)
```

If a WebR chunk uses a package, list the package in the YAML:

webr:
  packages:
    - ggplot2
    - dplyr

The slide deck should include the WebR helper file. For files inside Chapter Slides/, the path is:

{{< include ../_extensions/r-wasm/live/_knitr.qmd >}}

Do not use install.packages() inside WebR chunks. Packages should be declared in the YAML instead.

10. Quiz Slides

The project uses the reveal.js quiz plugin for multiple-choice quiz slides.

Make sure the YAML includes:

revealjs-plugins:
  - quiz

Use this structure for quiz slides:

---

##  {.quiz-question}

:::: {.callout-note icon="false"}
## Example

Question text goes here.
:::

- Wrong option
- [Correct option]{.correct data-explanation="Explanation goes here."}
- Wrong option
- Wrong option

Rule: Keep quiz questions short. Each quiz should test one idea only, and the explanation should tell students why the correct answer is correct.

11. Interactive JavaScript Widgets

Some slides include interactive JavaScript widgets, such as distribution explorers or tail-probability visuals.

These are not separate apps. They are written directly inside the Quarto slide file using HTML, canvas elements, sliders, and JavaScript.

These widgets usually have two parts:

  1. An HTML block containing sliders, labels, and a <canvas>.
  2. A <script> block that updates the drawing when the sliders move.
<div id="example-widget">
  <input type="range">
  <canvas id="example-canvas"></canvas>
</div>

<script>
window.exampleUpdate = function () {
  // JavaScript drawing code goes here
};
</script>

Do not delete the <script> block. The sliders and canvas may still appear, but the widget will not update without the JavaScript.

If a widget does not work, check that the HTML id names match the JavaScript, the slider calls the correct function using oninput, and the same IDs are not duplicated elsewhere.

12. Rendering and docs

After editing a source file, render it to create the updated HTML output.

To render the whole website:

quarto render

To render only one slide deck:

quarto render "Chapter Slides/chapterN-slides.qmd"

The docs/ folder contains the rendered website output that GitHub Pages serves.

Before publishing, check the homepage, chapter landing pages, slide decks, PDF links, images, WebR chunks, quizzes, and interactive widgets.

Never manually edit files inside docs/. Any manual edits may be overwritten the next time Quarto renders the website.

13. GitHub Workflow and Common Commands

Because this repository has folders with spaces in their names, use quotation marks around file paths in Git commands.

A safe Git workflow is:

git status
git add "path/to/file"
git status
git commit -m "Describe the change"
git push

Example for updating one slide deck:

git status
git add "Chapter Slides/chapterN-slides.qmd"
git status
git commit -m "Update Chapter N slides"
git push

If rendering changes files in docs/, also add only the matching rendered files shown by git status.

git add "docs/Chapter Slides/chapterN-slides.html"

Other useful commands

quarto preview
quarto render
quarto render "Chapter Slides/chapterN-slides.qmd"
quarto clean
quarto clean --all

14. Common Slide Errors and Known Issues

Broken links

Links should point to rendered .html files, not source .qmd files.

Correct:
<a href="../Chapter Slides/chapterN-slides.html">Open Chapter N Slides</a>

Incorrect:
<a href="../Chapter Slides/chapterN-slides.qmd">Open Chapter N Slides</a>

PDF button not working

PDF links should point to the rendered slide deck with ?print-pdf.

Correct:
../Chapter Slides/chapterN-slides.html?print-pdf

Incorrect:
../Chapter Landing Pages/chapterN.html?print-pdf

Image not loading

Check the path and capitalization.

![](images/cat.png)
![](../images/cat.png)

WebR not working

Check that the chunk uses {webr}, the WebR helper include exists, required packages are listed in YAML, and the code does not use install.packages().

{{< include ../_extensions/r-wasm/live/_knitr.qmd >}}

Quiz not working

Check that the YAML includes revealjs-plugins: - quiz, the slide has {.quiz-question}, and the correct answer uses {.correct data-explanation="..."}.

Interactive widget not working

Check that the HTML IDs match the JavaScript IDs, the slider calls the correct update function, the <script> block is still present, and the same widget IDs were not duplicated elsewhere.

Rendering error

Common causes include broken YAML indentation, missing closing backticks, broken HTML tags, wrong file names, wrong image paths, package errors, or trying to render the wrong file.

Fix the first error first. Later errors are often caused by the first one.

Final Note

The main rule for maintaining this project is simple: keep the source .qmd files organized, render before publishing, and keep chapter structure consistent across the site.
