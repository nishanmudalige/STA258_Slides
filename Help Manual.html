STA258 Website Help Manual

This manual explains how to maintain and troubleshoot the STA258 slide website.

It is written for future students, TAs, or project maintainers who take over the repository.

1. Purpose of this manual

This manual is not meant to explain every line of code. It is meant to help someone understand which files matter, what each one controls, and what to check when something breaks.

2. Files of importance

index.qmd

This is the main website landing page. It controls the page where students choose chapters.

Edit this file when changing the main homepage text, chapter cards, chapter links, or resource links.

chapter1.qmd, chapter2.qmd, chapter3.qmd

These are the chapter landing pages.

Each landing page gives a short overview of the chapter and links students to the slide deck and PDF version.

Edit these files when changing the chapter overview page, not when changing the slides themselves.

chapter1-slides.qmd, chapter2-slides.qmd, chapter3-slides.qmd

These are the actual slide decks.

Edit these files when changing lecture slide content, WebR examples, practice exercises, solutions, plots, or slide navigation.

styles.css

This controls shared website styling.

Edit this file when changing the general appearance of the website, such as cards, spacing, buttons, colours, or fonts.

_quarto.yml

This controls project-wide Quarto settings.

Only edit this file for project-level changes, because it can affect the whole website.

docs/

This folder contains the rendered website output.

Normally, do not edit this folder directly. Edit the source .qmd files, then render again.

3. Which file to edit

Home page issue       → edit index.qmd
Chapter overview      → edit chapterX.qmd
Slide content         → edit chapterX-slides.qmd
General styling       → edit styles.css
Project settings      → edit _quarto.yml
Rendered website      → generated in docs/ after rendering

4. Which files to render

Render the source .qmd files.

index.qmd
chapter1.qmd
chapter1-slides.qmd
chapter2.qmd
chapter2-slides.qmd
chapter3.qmd
chapter3-slides.qmd

The HTML help manual is a guide document and does not need to be rendered through Quarto.

5. Link rules

Use consistent links between landing pages, slide decks, and PDF versions.

chapter3.qmd → chapter3.html
chapter3-slides.qmd → chapter3-slides.html
PDF link → chapter3-slides.html?print-pdf

Avoid old temporary links like:

test.html

6. If a link is broken

  1. Check that the file name in the link is correct.
  2. Check that the matching .qmd file exists.
  3. Check that the file has been rendered into .html.
  4. Check that the link points to the rendered .html file, not the source .qmd file.

Example:

<a href="chapter3.html">Open</a>

This should correspond to:

chapter3.qmd → chapter3.html

7. If WebR does not work

  1. Check that the file is a slide deck such as chapter2-slides.qmd.
  2. Check that the code chunk uses {webr}.
  3. Check that the _extensions/ folder still exists.
  4. Check that the slide deck includes the WebR helper line.
  5. Check that required packages are listed in the YAML.
  6. Do not use install.packages() inside WebR chunks.

Example YAML:

webr:
  packages:
    - ggplot2

If using ggplot2, also load it inside the relevant code chunk:

library(ggplot2)

8. If WebR solutions do not show

Check that the exercise name and solution name match exactly.

#| exercise: sample-mean

must match:

::: {.solution exercise="sample-mean"}

If the names are different, the solution may not attach to the correct exercise.

9. If an image does not load

Check the image path in the file where the image is used.

If the code says:

![](cat.png)

then the image file must be in the expected location and the name must match exactly.

If the image is moved into another folder, update the path.

![](images/cat.png)

10. If the PDF button does not work

PDF buttons should point to the rendered slide deck with ?print-pdf added.

chapter3-slides.html?print-pdf

If the PDF button fails, check that the slide deck renders and that the link points to the slide deck, not the chapter landing page.

11. If rendering fails

Read the first error message. Common causes include broken YAML, missing backticks, broken HTML tags, wrong file names, image path errors, package issues, or trying to render the wrong type of file.

Fix the first error first, then render again.

12. Final check after rendering

After rendering, open the website in the browser and check that the main pages, chapter pages, slide decks, PDF buttons, images, WebR chunks, solutions, and back links work as expected.
